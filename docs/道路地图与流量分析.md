# 道路地图与流量分析

## 地图与空间档案

“道路地图”以本地纽约区域参考底图显示水域、绿地、建筑、道路名称和必要公共地标，再叠加 LION 26b 业务道路、事故及采样地点。参考底图来自 2026-10-27 的 OpenStreetMap／Protomaps 快照，不参与事故关联、风险评分或流量统计；与历史业务路网不完全重合属于不同来源／版本的差异。地图、字体和图标均从本机读取，日常使用不请求在线瓦片。

浅色与深色地图跟随系统外观切换。全市视图显示五区及周边地理参照；“回到全市”恢复城市范围，保留日期、行政区和附近查询条件。“重置”同时清除筛选与选中对象。街区级别加载业务道路（zoom 13 起），进一步放大显示路口（zoom 15 起），采样地点从 zoom 12 起显示。事故较密集时按网格聚合，点击查看准确数量和放大入口，也可通过“查看地图数据”使用键盘查阅，`k` 表示千；符号大小与数字不代表风险分值。行政区筛选采用事故业务记录的行政区字段，其来源报告／空间推导依据可在事故档案查看。

选择日期和行政区后应用筛选；拖动、缩放地图会同步事故列表。使用“按名称定位”查找道路、路口或采样地点，核对来源编号及位置后选择。点击业务对象可进入档案或选择附近事故；列表“定位”会滚动到地图。所选对象查询同时受视野、日期、行政区及 50—500 米范围约束；阴影表示附近范围，最终资格由数据库米制距离判定，邻近并不证明事故属于该对象。清除选择可恢复当前视野查询。筛选、视野、图层和页码写入地址，可重新打开复现。

关闭事故图层只隐藏符号，列表及总数保持不变。地图移动时保留上一次结果并显示更新提示，仅最新范围的响应会更新画面。列表翻页不会重新构建道路图层。查询失败会明确提示当前结果尚未更新，可调整条件后重新应用筛选。

页面每次最多显示道路 3,000 条、路口及采样地点各 800 个、单独事故点 1,200 个；超过阈值给出提示或转为聚合。事故列表每页 25 条，保留完整结果数量。缺少坐标的事故不能出现在地图中，但仍可在事故档案检索。

业务道路上限不限制参考底图路网。底图原生层级为 0—15，界面最多放大至 19；超过原生层级继续放大现有矢量，不代表获取了新的测绘精度。底图内容也不保证现实中所有建筑或设施都被收录。地图统一使用详细底图，需要浏览器支持 WebGL 并启用图形加速。加载失败时可点击“刷新地图”重试；资源缺失时由管理员按下方步骤恢复。事故档案、图表和结果列表仍可独立使用。

## 研究范围与其他模块地图

道路地图、综合统计内嵌地图和行政区／道路／路口历史风险地图使用同一套本地详细底图、主题、比例尺与研究范围。全市单一风险结果以汇总展示。

蓝灰色长虚线为纽约市研究范围（26b 行政边界，含水域）；细短虚线为内部区界，范围外背景略作弱化。五区名称放置在陆域内，街区级别减少名称遮挡。默认开启的“研究范围”开关只影响显示，不添加筛选，也不裁掉桥梁或边界外的合法业务记录。街区缩放时处于视野内的市界仍可辨认。

统计地图保留自己的已应用条件，平移仅改变显示；“按当前视野统计”才提交分析范围，紫色短虚线表示该范围，“解除视野范围”保留其他条件。风险点位继续表示该次结果中保存的代表位置，分数和支撑量不因缩放或切换外观而改变。地图角落保留来源署名，边界图例显示“纽约市研究范围”；资源版本和部署信息在本文及资源清单中查阅。内嵌详细地图按住 Ctrl 配合滚轮缩放，触屏用双指移动，也可使用加减按钮；其余滚动用于浏览页面。

## 离线底图部署

区域包位于 `data/basemaps/nyc-20261027.pmtiles`，通过 Git LFS 跟随版本管理，与数据库业务表分开。新克隆先执行 `git lfs pull` 和 `git lfs fsck`，确认取得完整地图；已有安装不必重新下载。包只用于地图背景，采用按需分段读取。固定版本、区域、下载来源和校验信息保存在 `config/map_resources.json`；本地资源许可见[第三方资源说明](第三方资源说明.md)。既有安装可直接使用，不需要重新采集业务数据或导入数据库。

在新设备重建时，可从 [Protomaps 官方发行页](https://github.com/protomaps/go-pmtiles/releases/tag/v1.31.2)取得 PMTiles CLI 1.31.2，并在项目根目录执行：

```powershell
python scripts/prepare_map_assets.py --work-dir var/map_setup --pmtiles-cli "<PMTiles工具路径>"
```

安装器使用固定版本资源，核验完整性，仅提取纽约及周边区域（西经 74.65—73.30、北纬 40.35—41.06）；下载并发为 2，不下载全球完整包。不安装独立瓦片服务，运行时不启动下载、底图转换或持续后台计算。缺少离线包时分析模块仍可查看图表和列表；重建仅在明确执行安装命令时联网。

研究范围显示文件已随源码提供：`static/data/nyc_research_boundary.geojson`，约 215 KB。它由固定 26b 含水域五区边界派生，保留岛屿与孔洞，在 EPSG:2263 中按 5 米容差做拓扑保持简化后转回 WGS84；不替代数据库测量几何。需要从原始快照重新生成时执行 `python scripts/prepare_map_boundaries.py`，无需联网或修改数据库。

“道路与路口”可按名称、来源编号、行政区、网络版本检索；“全部来源要素”还包含非道路、虚拟中心线及未确定节点。同来源路段编号用稳定代表要素组织查询，全部原始要素仍保留。不同几何或关键属性的组不作为自动匹配候选。路口分类综合来源层级、虚拟节点、地面连接数与街道名称，来源拓扑节点不直接等于实地路口。

## 匹配规则与维护

事故与采样地点的关联是独立实体，内部主键与各数据集来源标识分开。候选仅来自同一目标网络的有效实际机动车道路；空间查询利用 GiST 索引和包围盒，再以 `geography` 计算米制距离。

| 条件 | 当前派生规则 |
|---|---|
| 道路候选 | 80 米内，最多 12 条近邻；只用无来源几何／属性冲突的代表要素 |
| 来源编号关联 | 采样编号标准化后相符，并同时通过名称、方向、25 米距离核查 |
| 名称关联 | 名称标准化一致、25 米内；多个同名候选要求与次近候选至少相差 8 米 |
| 无来源街名 | 12 米内唯一近邻且距离差至少 8 米；不以近邻覆盖明确不符的街名 |
| 路口关联 | 双街名相符、15 米内唯一已识别路口；无街名时仅采用 8 米内独立近邻 |
| 方向对照 | 起终点方位与 NB／SB／EB／WB 对照，最大角差 50°；W 沿节点方向、A 逆向、T 双向 |
| 人工校正 | 维护角色填写依据，目标同网络且有效，距离不超过 200 米；保留前后值与操作者 |

“空间关联台账”可按事故／采样地点、目标网络、行政区及状态检索，展示关联、未匹配、缺少位置和待核查数量；输入已修订可单独筛选。候选名称、编号、距离、规则版本和未匹配原因可在“关联证据”查看。多候选、来源不符和缺少位置分别保留为明确状态，不强行选取第一条。人工确认仍是带证据的项目判断，并非官方已确认事故归属。

维护人员可修改道路、路口、采样地点的展示名称、说明和有效状态；路口分类可复核。来源身份和几何受数据库保护。对象修订号变化后旧关联标记待更新，不用于可靠统计。事故空间页支持首次建立关联、重新计算、确认指定候选或确认未匹配；地点档案提供相同入口。已人工确认且输入未变的关联在批量重建时保留。

批量重建在项目环境执行 `python manage.py rebuild_spatial --network-id <网络内部编号>`；中断后使用 `--resume <批次 UUID>`。命令与导入／维护共享互斥锁，每批对象及检查点同事务提交。该命令生成派生关联，不下载、覆盖或删除来源数据。

## 流量查询与完整性

“交通流量”按采样请求、街道、行政区、方向或关联道路检索；每个地点页面提供来源观测日期、15 分钟明细、小时／日汇总、曲线及高峰统计。明细可以按每日开始／结束时刻筛选；该筛选仅作用于原始明细，整日完整性和汇总不随之截短。观测是临时采样，起止日期之间也可能缺测。默认展示最早有观测日起七天内的范围。

每个地点、当地日期、当地时隙只能有一条有效、时间唯一的官方已发布观测。重复来源行即使数值相同也不能累加；冲突、排除和模糊时刻不进入可靠流量。时隙由纽约午夜至次日午夜的真实 UTC 时间轴生成：普通日 96 个，春季切换日 92 个，秋季切换日 100 个；没有偏移证据的重复小时继续受限。

- 真实零流量显示为 0；缺测显示空缺，不补零。
- “有效观测小计”只合计可用时隙；“完整总量”要求窗口全部时隙有效，否则为空并说明不完整。
- 曲线完整时段为实线，部分小计单独标记，缺测断线；下方表格给出等价数值和覆盖状态。
- 早高峰固定 07:00—10:00，晚高峰固定 16:00—19:00，均为三小时；不把部分观测外推为完整窗口。
- 查询最大天数为 15 分钟粒度 31 天、小时 93 天、每日 366 天；超限返回明确校验提示。

期间比较采用相同天数及“相对日序＋当地时刻＋重复小时标记”对齐，只比较两段共同有效时隙。同一地点、方向和起始星期一致时提供变化差值；地点、方向、星期构成不同时只展示并列观测和原因。零基数不提供百分比。比较图保留不共同有效时隙的空缺，明细可分页核对。可比不表示完全控制了天气、节假日或临时管制等因素。

## 事故与观测暴露量

页面始终区分所选日期的道路已关联历史事故数与实际观测时隙内的分子。可靠比值要求：

1. 当前有效且无来源歧义的同一道路关联；同一采样请求下具有唯一反向地点。
2. 两个方向已人工核实所选历史期间的道路几何、行车方向与采样覆盖，核查证据包含起止日期及当前目标修订号。当前 LION 几何不自动证明历史道路未变化。
3. 两方向使用完全相同的有效 UTC 15 分钟时隙，观测合计为正。
4. 事故当前匹配到该路段且发生在这些真实时隙内；附近存在时间不确定、未匹配或过期关联事故时停止计算并说明原因。

满足条件时显示“观测范围内每百万辆次匹配事故数”。它只覆盖有位置、有效道路关联和确定时间的事故，排除路口事故，不能解释为完整道路风险或个人出行概率。未定位事故无法分配道路，须保留这一限制。当前未提供人工历史覆盖证据的地点不会出现该比值；仍可查询流量和已关联历史事故。禁止将全年事故数除以少量采样日流量。
