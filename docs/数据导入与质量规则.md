# 数据导入与质量规则

## 来源与范围

事故、车辆、人员和交通流量采用 NYC Open Data 的全字段快照。课程交付范围为纽约五区 2021-01-01 至 2025-12-31 的全部已发布记录；缺失行政区或坐标的事故仍然保留。来源公开数据可能滞后或修订，采集时间与事件截止日期分别记录。清单截止日期表示筛选上界，不表示流量在每一天都有观测；覆盖核对另列实际首末观测日。

| 数据 | 官方来源 | 主键与范围 |
|---|---|---|
| 事故 | [Motor Vehicle Collisions - Crashes](https://data.cityofnewyork.us/d/h9gi-nx95) | collision_id；按 crash_date 分年 |
| 车辆 | [Motor Vehicle Collisions - Vehicles](https://data.cityofnewyork.us/d/bm4k-52h4) | unique_id；按本表 crash_date 分年 |
| 人员 | [Motor Vehicle Collisions - Person](https://data.cityofnewyork.us/d/f55k-p6yu) | unique_id；按本表 crash_date 分年 |
| 流量 | [Automated Traffic Volume Counts](https://data.cityofnewyork.us/d/7ym2-wayt) | 保留 Socrata 系统行号；按 yr 分年 |
| 道路与节点 | [LION](https://data.cityofnewyork.us/d/2v4z-66xt) | 固定 26b 官方 File Geodatabase 档案；全部道路要素和节点 |
| 行政边界 | [含水域边界](https://data.cityofnewyork.us/d/wh2p-dxnf)、[陆域边界](https://data.cityofnewyork.us/d/gthc-hcne) | 同版 26b；含水域几何用于行政归属，陆域文件另存 |

原始响应按页压缩保存，空间 ZIP 及其原生数据库保留。清单记录版本、查询范围、字段、分页地址、前后数量、来源修改时间、采集时间及内部完整性摘要。查询计数仅用来核对该次快照，不是永久写死的验收数量。采集中来源版本或行数变化时不发布混合快照。

## 运行与恢复

在已配置的项目根目录执行以下命令；下载与重型导入均在命令行运行，不占用 Web 请求。示例中的 `nyc_snapshot` 为只含英文字母、数字、连字符或下划线的目录标签，同一来源状态重试沿用同一标签；需获取修订版本时使用新标签。

```powershell
python scripts/acquire_nyc.py --start 2021-01-01 --end 2025-12-31 --label nyc_snapshot
python scripts/acquire_spatial.py --label nyc_snapshot
python manage.py import_official --label nyc_snapshot
python manage.py verify_official --label nyc_snapshot --publish --output var/quality_report.json
```

导入前保留数据库备份。下载脚本采用有上限的重试与分页。导入命令核验全部输入页后依次导入边界、节点、道路、事故、车辆、人员、流量。默认每 2,000 行一个事务，用应用账户通过 [COPY FROM STDIN](https://www.postgresql.org/docs/17/sql-copy.html) 批量写入；无服务器文件读写或超级用户要求。事务同时提交原始行、业务行、附属因素、质量问题和断点。失败事务整体回滚，错误类型写入批次；再次执行创建新尝试并从已提交断点继续。会话级咨询锁防止两个导入进程同时执行。发布完成后更新相关表的查询规划统计信息，使本机读取使用与实际数据规模匹配的计划。

相同完成快照再次运行返回已有结果。新快照中同来源主键且内容相同的行保留原始证据、跳过重复业务写入；内容不同的行进入待核查，不能覆盖既有事实或人工修正。清单或原始页校验失败时停止导入。后续网页任务提交、修正和冲突处理入口另行提供。

## 字段与关系

- 原始 JSON 载荷、来源身份和行号由数据库触发器保护；标准化仅作用于业务字段。来源多余字段仍在原始载荷中保留。
- 缺失伤亡、年龄、车辆年份、坐标不替换为 0。负数、非整数、无穷数和超出物理字段范围的计数转为未知并生成质量问题；年龄大于 130、明显不合理的车辆年份同样处理。车型、因素、损伤位置按来源列映射，事故因素槽位不猜配具体车辆。
- Vehicles.collision_id 和 Person.collision_id 关联 Crashes.collision_id。Person.vehicle_id 关联 Vehicles.unique_id，而不是车辆 UUID。孤立引用保留原键，内部外键为空；车辆与人员事故不一致时不建立该车辆关系。子表来源日期／时刻与事故不同会被记录。
- 非空但不合理的事故位置不进入可用几何，原始值仍可复核。来源行政区保留；缺失行政区仅在一个官方边界唯一包含该点时作空间推导。来源报告与空间归属冲突会记录，不能静默更改。
- 节点编号在关系匹配时去除数字前导零，原始字符串不改写；SegmentID 保留原文，路段唯一身份采用网络版本与档案 FID。节点未全部认定为实际交叉路口。

## 时间与空间

事件日期和时刻按 America/New_York 解释。分别保存当地时间、UTC 时间及转换状态。秋季重复小时和春季不存在时刻不任意选择或平移，UTC 留空。缺失时刻不补成午夜。正式流量表采用 15 分钟槽位；非标准分钟记录留在暂存隔离层，不强制对齐。若一个地点同时出现标准与非标准分钟，标准子集也不参与可靠统计，避免只接受部分记录改变采样含义。

LION 26b 原生 CRS 为 EPSG:2263，单位 US survey foot；长度乘以 1200/3937 转为米，几何转为 EPSG:4326。行政区接口提供经纬度 GeoJSON。流量 WKT 的官方字段说明没有明确 CRS 编号，其 EPSG:2263 解释属于基于坐标范围、五区边界和道路邻近距离的验证推断；证据与统计另见快照质量核对。推断结果不能代替流量 LION 14 编号与 26b 道路之间的正式匹配。

## 冲突、统计资格与数量守恒

流量地点的候选身份为请求、来源路段与方向。相同地点、日期、时刻具有不同 volume 时，所有成员保留并指向独立 FlowConflict；不求和、平均或任选一条。流量官方附带的位置／方向纠错清单原文保留，受影响请求和路段保守排除；其中日期更正也不直接改写事实。

可靠流量仅使用 `origin=official`、`is_active=true`、已发布快照、`quality_status=valid`、无冲突且可唯一转换时间的观测。来源通告、冲突、不可确定的当地时刻或不可靠坐标排除在外。重复同值槽位单独核验；发现未处置重复时发布验收失败。采样覆盖不连续，真实观测 0 与没有观测行的缺测不同。可靠观测还需要通过地点和窗口可比性检查，才能用于事故暴露量指标。

对每个快照，源记录数应等于暂存记录数，并等于“接受＋拒绝＋待核查＋重复跳过”。有质量警告但仍可使用的事故／车辆／人员可以归入接受；被隔离的流量仍保留业务行，因此业务行总数可以大于接受数。最终报告同时列出业务行数、原始行状态和关系／字段问题，避免误读“部分成功”为数据丢失。重试批次的累计计数不能跨尝试相加。

发布前核对五年完整范围、来源／暂存数量、孤立关系、行政区、时间状态、空间有效性和流量冲突。公开快照附带质量限制不等于所有记录毫无问题；未处理问题保持开放并留待有依据的核查。

## 页面任务与后续文件

当前可通过“导入任务”上传四类官方业务来源文件，由本机后台进程校验、排队及分批入库。文件范围、限制、失败重试与操作者权限见[业务操作与维护](业务操作与维护.md#文件校验与后台导入)。普通业务上传不替代道路／行政区的成套空间版本接入。

新增流量文件与已有已核验快照共同检查同地点、方向及当地时刻的观测。来源编号不同但观测时段重复的记录，包括流量值相等的记录，也保留并隔离，防止重复计数。分组冲突不会自动选择赢家。质量核查状态独立于流量统计资格。

网页上传的文件均明确标记为局部文件范围，不据此重新声明完整五年覆盖；原文件与来源原始载荷都保留。CLI 全量版本核对与网页局部文件核对采用各自适用的范围。
