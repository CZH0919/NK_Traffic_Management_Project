| [一级数据流图](07_dfd_level1.svg) | 六类处理与五组数据存储 | 全系统逻辑流程 |

E-R 图采用关系实体框及关联基数；箭头由主实体指向引用实体。`0..1:N` 表示引用端可没有已解析的父对象，不能据此创建虚假的父记录。事故来源槽位与车辆来源记录没有按序号建立外键。道路网络与流量来源的版本不同，匹配关联由独立的当前物理实体承载。

图为按业务主题分图的全系统模型，不是单张物理数据库反向工程图。来源引用、用户引用及版本引用在不同图中可重复出现；这些是同一实体。图中文字不宣称逻辑流程已经实现。

可使用 `python scripts/render_design_diagrams.py` 重建 SVG 和 Mermaid 源；验收用 PNG 由同一坐标定义生成，保存在内部证据目录。

## 上下文与一级处理的外部流对齐

一级图展示内部主要处理与存储，外部接口沿用上下文图。各跨边界数据流对应如下，不能把外部数据直接写入业务事实存储。

| 外部流 | 一级处理 |
|---|---|
| 官方文件与元数据输入 | P1 接收并形成 D1 证据 |
| 用户维护与核查请求 | P2 处理并写 D2、D5 |
| 用户查询条件、明细与图表结果 | P3 接收条件并返回查询结果；P4 提供派生分析 |
| 用户报告请求、报告与简报结果 | P5 接收请求、返回结果并写 D4 |
| 确定汇总上下文 → 模型 API | P5 仅发送已经计算的汇总 |
| 模型 API → 生成文本 | P5 校验、保存原始文本并支持编辑 |
| 管理员账户/维护请求及结果 | P6 校验权限，执行受控维护并记录 D5 |
