# 版本控制与目录规范

仓库根目录是日常开发和本机测试的唯一当前源码位置。`main` 保存最新可测试版本，并跟踪 `origin/main`；远端为 [CZH0919/NK_Traffic_Management_Project](https://github.com/CZH0919/NK_Traffic_Management_Project)。

## 目录职责

| 目录／文件 | 职责 |
|---|---|
| `apps/`、`config/`、`manage.py` | Django 应用、数据库迁移、配置和管理入口 |
| `templates/`、`static/` | 页面、样式、脚本和本地第三方资源 |
| `scripts/` | 采集、资源准备、启动、停止、备份和维护等可复用工具 |
| `tests/` | 正式自动化回归测试 |
| `docs/`、`readme.md` | 使用、设计、数据口径、部署和资源许可说明 |
| `data/manifests/` | 经核查的正式数据来源与完整性清单 |
| `data/raw/`、`data/basemaps/` | 指定官方快照和离线地图，使用 Git LFS |
| `requirements-lock.txt`、`.env.example` | 固定依赖与无秘密的配置示例 |
| `AGENTS.md`、`.editorconfig`、`.gitattributes` | 协作、文本编码、资源字节及 LFS 规则 |
| `Agent_Handoff/`、`Project_Progress/` | 原工作区的内部交接、阶段进展与验证证据；不发布 |
| `Traffic_Venv/`、`.env`、`var/` | 本地解释器、私有配置、数据库备份、恢复副本和运行文件；不提交 |

原工作区保留已约定的需求／规划文件路径作为协作入口。历史研究、一次性诊断脚本和旧日志集中归档到 `Project_Progress/archive/`，不属于当前执行工具或正式源码。

## 日常操作

```powershell
git status --short --branch
git fetch origin
git log --oneline --decorate -5
git pull --ff-only
git lfs pull
```

拉取前确认本地改动已经妥善保存。更新后按需要重启本机服务；`git pull` 本身不会重启服务、执行迁移或更新数据库。

准备提交时先查看 `git diff`，只暂存本次相关文件，使用能说明目的的提交信息。推送后核对本地提交与远端 main；不得为追求一致而用强制推送、硬重置或清空工作区覆盖未核对的内容。

```powershell
git diff --check
git diff --cached --stat
git status --short
git push origin main
git rev-parse HEAD
git ls-remote origin refs/heads/main
```

新功能是否使用独立开发分支、是否推送，以当次协作约定为准。备份分支不承担新功能开发。

## 数据与发布边界

固定官方数据和离线底图已纳入 LFS，清单使用普通 Git。当前数据约 681 MiB，单个最大文件约 191 MiB，超过 GitHub 普通 Git 的 100 MiB 文件上限；使用 [Git LFS](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage) 可保留版本关联并避免把二进制内容直接塞入普通提交。

LFS 的存储和下载计入仓库所有者额度，详见 [GitHub LFS 计量规则](https://docs.github.com/en/billing/concepts/product-billing/git-lfs)。固定快照无需每次迭代重复改写；新数据版本应经过来源、敏感信息、完整性与容量核对，不自行调整账户付费设置。

真实密码、API Key、账户凭据、数据库物理目录／逻辑备份、用户上传与导出、虚拟环境、缓存和内部开发证据均不进入公开仓库。Git 记录代码与正式来源文件；现有业务库和账户状态仍按数据库维护流程备份恢复。
